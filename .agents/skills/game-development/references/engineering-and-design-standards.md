# มาตรฐานวิศวกรรมเกม การออกแบบ และลิขสิทธิ์ (Engineering, Game Design & Asset Standards)

เอกสารนี้กำหนดมาตรฐานทางเทคนิคและการออกแบบเกมของ **"Game Dev Partner"** (`/game-development`) สำหรับคุณ **game**

---

## 1. มาตรฐานวิศวกรรมโค้ดเกม (Engineering Standards)

1. **เทคโนโลยีหลัก (`Default Tech Stack`):**
   - ใช้ `HTML / JS / CSS (Canvas 2D หรือ WebGL)` เป็นค่าเริ่มต้นสำหรับเกมบน Web และ Windows 11 PC
   - การเสนอเอนจินหรือเฟรมเวิร์กอื่น (เช่น Phaser, Three.js, PixiJS, Godot, Unity, Roblox Luau) ถือเป็น **BIG Decision** ที่ต้องอธิบายข้อดี/ข้อเสียและขออนุมัติจากคุณ `game` ก่อนเสมอ
2. **การแยกส่วนประกอบของโค้ด (`Modular & Clean Architecture`):**
   - แยกไฟล์หรือโมดูลค่าคงที่และการตั้งค่า (`config.js` / `constants.js`) ออกจากลอจิกการเล่น (`gameplay logic`) เสมอ เพื่อให้คุณ `game` ปรับจูนความเร็ว ดาเมจ หรือความยากได้ง่ายในจุดเดียว
   - ตั้งชื่อตัวแปรและฟังก์ชันเป็นภาษาอังกฤษที่สื่อความหมายชัดเจน เขียนคอมเมนต์อธิบายเหตุผล (**WHY**) ไม่เขียนคอมเมนต์บรรยายสิ่งที่โค้ดบอกอยู่แล้ว
3. **ลูปเกมที่ไม่ผูกกับเฟรมเรต (`Frame-Rate-Independent Game Loop`):**
   - คำนวณการเคลื่อนที่และฟิสิกส์ด้วย `deltaTime` (เวลาที่ผ่านไปจริงระหว่างเฟรม พร้อมเพดานจำกัดค่าสูงสุด `maxDeltaTime` กันเกมกระโดดเวลาสลับหน้าต่าง) หรือใช้ `Fixed Timestep` เพื่อให้เกมเล่นด้วยความเร็วเท่ากันทั้งบนจอ 60Hz และ 144Hz+
4. **การจัดการหน่วยความจำและประสิทธิภาพ (`Object Pooling & Zero Per-Frame Allocation`):**
   - ห้ามใช้ `new` สร้างออบเจกต์หรืออาร์เรย์ใหม่ใน `update()` หรือ `render()` ที่รันทุกเฟรม เพื่อป้องกัน `Garbage Collection (GC) Spikes` (อาการเกมกระตุกเป็นจังหวะเมื่อเบราว์เซอร์เคลียร์แรม)
   - ใช้ `Object Pool` สำหรับกระสุน พาร์ทิเคิล ศัตรู และข้อความดาเมจลอย (`Floating Damage Numbers`)
   - มีระบบ `Quality Settings` (เช่น `Low / Medium / High` สำหรับปรับจำนวนพาร์ทิเคิล เงา หรือความละเอียด Canvas) เพื่อให้เล่นได้ลื่นแม้บนเครื่องสเปกต่ำ
5. **ระบบบันทึกข้อมูลแบบระบุเวอร์ชัน (`Versioned Save System`):**
   - ข้อมูลเซฟทุกชิ้นต้องมีฟิลด์ `schemaVersion` (เช่น `{ "schemaVersion": 1, "timestamp": ..., "playerProfile": ... }`) พร้อมฟังก์ชันแปลงเซฟเก่า (`migrateSaveData`) และระบบป้องกันเซฟเสีย (`Fallback / Validation`)

## 2. เกณฑ์เกมที่เสร็จสมบูรณ์และขัดเกลาแล้ว ("Finished and Polished" Checklist)

ก่อนจะถือว่าโปรเจกต์เกมใดสมบูรณ์พร้อมขึ้นพอร์ตโฟลิโอหรือวางขาย ต้องมีองค์ประกอบครบ 7 ข้อนี้:
- [ ] **1. Menu:** หน้าเมนูหลัก หน้าหยุดเกมชั่วคราว (`Pause Menu`) และหน้าตั้งค่า (`Settings / Quality / Audio Volume`)
- [ ] **2. Sound:** เสียงเอฟเฟกต์ (`SFX`) และเพลงประกอบ (`BGM`) ที่ปรับระดับเสียงหรือปิดเสียงได้
- [ ] **3. Effects (`Juice`):** เอฟเฟกต์ภาพตอบสนองการกระทำของผู้เล่น (เช่น พาร์ทิเคิล, แสงแฟลช, หน้าจอสั่นเบาๆ ที่เปิด/ปิดได้)
- [ ] **4. Tutorial:** ระบบสอนเล่นหรือคำแนะนำปุ่มกดในเกมที่เข้าใจได้ทันทีโดยไม่ต้องอ่านคู่มือยาวๆ
- [ ] **5. Save System:** ระบบบันทึกความคืบหน้าหรือสถิติสูงสุดแบบมี `schemaVersion`
- [ ] **6. Characters:** ตัวละครผู้เล่นและศัตรู/NPC ที่มีเอกลักษณ์และแอนิเมชันตอบสนองชัดเจน
- [ ] **7. No Known Bugs:** ผ่านการทดสอบจาก `QA Tester` แล้วไม่มีบั๊กค้างคา

## 3. มาตรฐานการคัดเลือก Asset และการตรวจลิขสิทธิ์ (Asset & Licensing Protocol)

เพื่อแก้ปัญหาที่ปวดหัวที่สุดของคุณ `game` ในการหา Asset อย่างปลอดภัย:
1. **ลำดับการเลือกใช้:** ใช้ Asset ของคุณ `game` เองก่อน -> หากไม่มี ให้ `Technical Artist & Asset Scout` ช่วยค้นหา **FREE Assets** ที่มีสัญญาอนุญาตชัดเจน (เช่น `CC0 / Public Domain`, `CC-BY 4.0`, `MIT`) -> **ถามขออนุมัติก่อนดาวน์โหลดหรือนำมาใส่โปรเจกต์ทุกครั้ง**
2. **การตรวจสัญญาอนุญาตจริง:** ต้องอ่านข้อความ License บนหน้าเว็บต้นทางจริง ห้ามเดาจากชื่อเว็บ หากข้อความคลุมเครือหรือไม่ระบุสิทธิ์การใช้งานเชิงพาณิชย์ ให้ตีความเป็น **`NOT usable` (ห้ามใช้)** และแจ้งถามคุณ `game`
3. **การบันทึกใน `ASSETS.md`:** ทุกชิ้นต้องบันทึกครบทั้ง ชื่อ, ลิงก์ต้นทาง, ผู้สร้าง, ชนิดสัญญาอนุญาต, ต้องให้เครดิตหรือไม่, ใช้เชิงพาณิชย์ได้หรือไม่, วันที่ตรวจ, และหมายเหตุให้คนตรวจซ้ำก่อนขายจริง
